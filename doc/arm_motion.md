## 二、坐标系与姿态的基本概念

---

## 2.1 机械臂的基坐标系（Base Frame）

### 颜色约定

大多数机器人软件中，一般使用如下颜色表示坐标轴：

- `X`：红色
- `Y`：绿色
- `Z`：蓝色

### 定义

基坐标系（Base Coordinate System）通常是整台机械臂进行运动学计算和轨迹规划时的参考坐标系，也是建立各关节、各连杆坐标系的“零点”基础。

不同机器人厂商可能会有不同的默认设定，但一般都会遵循：

- 右手坐标系
- 第一关节主轴方向的通用约定

你可以把机械臂基坐标系理解成：

- 机械臂的“家”

所有目标点，最终都要转换成“相对于家有多远”的坐标来描述。

类比：

- “目标点在我家东边 3 米，北边 2 米，向上 1 米”

### 原点如何定义

多数六轴机械臂会把基坐标系原点放在以下位置之一：

- 底座安装面中心附近
- 第一关节 `J1` 的旋转轴中心线附近
- 底座与第一关节轴线相交的位置

这样做的优点是：

- 便于运动学建模
- 第一关节的旋转可直接围绕某个主轴展开
- 齐次变换矩阵表达更清晰

### 三轴方向如何定义

通常根据右手定则确定：

- `Z` 轴：通常与第一关节旋转轴重合
- `X` 轴：通常指向机械臂前方或主要工作区方向
- `Y` 轴：由右手定则自动确定

课程使用的 Episode 1 六轴机械臂也遵循这一原则。

### 练习

1. 打开 RoboDK
2. 导入 Episode 1 机械臂
3. 显示参考坐标系并放大
4. 自己用右手定则判断 X/Y/Z 三轴方向

## 2.2 工具/末端坐标系（Tool Frame / End Effector Frame）

### 定义

工具坐标系是相对于机械臂末端法兰或实际安装工具建立的坐标系，用于描述工具在空间中的位置和姿态。

常见用途包括：

- 示教
- 轨迹规划
- TCP 设置
- 碰撞检测
- 更直观地控制末端执行器

### 工具坐标系的放置位置

通常有两种常见方式。

### 1. 定义在末端法兰处

对通用六轴机器人来说，最基础的工具坐标系往往默认定义在法兰上。

特点：

- 原点是法兰中心或安装面中心
- 便于控制器先求解法兰位姿
- 适合作为后续工具补偿的基础

### 2. 定义在工具实际工作点 TCP

很多应用中，真正需要精确定位的并不是法兰，而是工具前端的工作点，例如：

- 吸盘吸附点
- 夹爪中心
- 焊枪电弧点
- 喷枪喷口

这时通常要定义一个新的工具坐标系，让其原点位于 `TCP（Tool Center Point）`。

这样做的好处是：

- 示教更直观
- 运动目标直接对应工具作用点
- 不需要每次手工补算法兰到工具尖端的偏移

### 工具坐标系的方向

工具坐标系同样遵循右手定则。

常见约定：

- `Z` 轴：沿工具主要工作方向
- `X` 轴：沿工具辅助方向或关键安装方向
- `Y` 轴：由右手定则自动确定

### 多工具场景

如果一台机器人会切换多种工具，例如：

- 抓手
- 相机
- 焊枪

那么每种工具都可以定义自己的工具坐标系。

控制器在激活不同 Tool Frame 后，就能自动处理：

- TCP 偏移
- 姿态补偿
- 对应的运动指令解释

### 与运动学的关系

在运动学计算中，通常先计算：

- 末端法兰位姿

如果定义了工具坐标系，则相当于在法兰坐标系上继续叠加一个刚性变换。

例如 Episode 1 的负压吸嘴：

- 沿法兰 `Z` 轴大约偏移 `48 mm`

因此工具坐标系相对于法兰的变换矩阵，通常可记为：

- `T_flange_tool`

### 练习

1. 下载 `负压吸盘.tool`
2. 在 RoboDK 中安装 TCP 工具
3. 观察工具中心点与法兰之间的相对位姿
4. 尝试修改 `Z` 偏移，感受 TCP 对运动效果的影响

## 2.3 位置与姿态（Position & Orientation）

---

## 2.3.1 位置（Position）

“位置”描述的是一个点在空间中的坐标位置。

例如：

- 末端执行器 TCP 在基坐标系下的位置为 `(500, 200, 150) mm`

这表示：

- X 方向 `500 mm`
- Y 方向 `200 mm`
- Z 方向 `150 mm`

### 定义

在某个参考坐标系下，一个点的位置通常用三维向量表示：

- `(x, y, z)`

其中：

- `x, y, z` 是该点在参考坐标系下的空间坐标
- 单位通常为 `m` 或 `mm`
- 它回答的是“这个点在哪里”

如果描述一个坐标系相对于另一个坐标系的位置，那么通常取：

- 该坐标系原点相对于参考坐标系原点的位置向量

---

## 2.3.2 姿态（Orientation）

“姿态”描述的是一个物体在空间中的朝向，也就是：

- 它不只是“在哪里”
- 还包括“怎么转的”

例如同样在 `(500, 200, 150) mm` 这个位置：

- 焊枪可能朝上
- 也可能朝下
- 也可能斜着朝前

这些差异就是姿态决定的。

常见姿态表达方式有：

- 欧拉角
- 旋转矩阵
- 四元数

本课程重点介绍：

- 欧拉角
- 旋转矩阵

因为它们在机器人运动学与视觉系统中最常见。

---

## 2.3.2.1 欧拉角（Euler Angles）

欧拉角使用三个旋转角度描述一个刚体的姿态。

常见形式：

- `ZYX`
- `XYZ`

每个角度表示绕某个轴的旋转。

旋转方向遵循右手法则：

- 面向轴的正方向时，正角度旋转为逆时针

### 示例 1：绕 Z 轴旋转 90°

若采用 `ZYX` 顺序，欧拉角：

- `[90, 0, 0]`

可以理解为：

- 绕 Z 轴旋转 `90°`
- 再绕 Y 轴旋转 `0°`
- 再绕 X 轴旋转 `0°`

这表示：

- 物体原本朝前的 X 轴，旋转后变成了朝右

### 示例 2：绕 Z 轴旋转 90°，再绕 Y 轴旋转 90°

若采用 `ZYX` 顺序，欧拉角：

- `[90, 90, 0]`

可以理解为：

- 先绕 Z 轴旋转 `90°`
- 再绕当前局部 Y 轴旋转 `90°`

### 内禀旋转与外禀旋转

欧拉角最容易混淆的地方在于“旋转到底绕谁的轴”。

#### 外禀旋转（Extrinsic Rotation）

每次旋转都绕全局固定坐标轴。

#### 内禀旋转（Intrinsic Rotation）

每次旋转都绕物体当前局部坐标轴，坐标轴会随着前一次旋转发生变化。

对大多数六轴工业机械臂来说，更符合直觉和物理结构的是：

- `内禀旋转`

因为每个关节都是绕当前连杆局部轴转动的。

### 注意：内禀旋转下 ZYX 和 XYZ 顺序影响很大

例如：

- `ZYX [30, 60, 90]`
- `XYZ [30, 60, 90]`

虽然角度数字相同，但最终姿态一般完全不同。

所以在使用欧拉角时，必须始终明确：

- 旋转顺序
- 是内禀还是外禀

### RoboDK 与 API 的注意事项

- RoboDK 中显示的欧拉角顺序并不总是固定
- 实际编程时建议以 `SE3` 代码和接口文档为准

Episode 1 API 支持：

- `ZYX`
- `XYZ`

有时逆运动学可能无解，这是正常现象。

## 2.3.2.2 旋转矩阵（方向余弦矩阵）

旋转矩阵是一个 `3 x 3` 的正交矩阵，用于表示一个坐标系相对于另一个坐标系的旋转关系。

### 几何含义

旋转矩阵的三列分别表示：

- 目标坐标系 `X` 轴在基坐标系中的方向向量
- 目标坐标系 `Y` 轴在基坐标系中的方向向量
- 目标坐标系 `Z` 轴在基坐标系中的方向向量

也就是说：

- 每一列都描述“目标坐标轴朝哪边”

### 示例 1：单位矩阵

若目标坐标系与基坐标系完全重合，则旋转矩阵就是单位矩阵：

- 目标 X 轴与基 X 轴一致
- 目标 Y 轴与基 Y 轴一致
- 目标 Z 轴与基 Z 轴一致

### 示例 2：绕基坐标系 Z 轴旋转 +90°

几何上：

- 目标 X 轴转到基 Y 轴方向
- 目标 Y 轴转到基负 X 轴方向
- 目标 Z 轴保持不变

旋转矩阵可以据此写出。

### 示例 3：绕基坐标系 Z 轴旋转 +30°

这时可通过三角函数写出旋转矩阵，矩阵中会出现：

- `cos(30°)`
- `sin(30°)`

### 单轴旋转矩阵

一般来说，绕单轴旋转都能写成标准形式：

- 绕 `X` 轴旋转
- 绕 `Y` 轴旋转
- 绕 `Z` 轴旋转

这些是后续构建复杂旋转的基础模块。

### 为什么需要旋转矩阵

旋转矩阵的优点在于：

- 可以直接参与线性代数运算
- 能无缝与平移组合
- 方便连续坐标变换连乘
- 在机器人、图形学、视觉中都统一适用

例如按 `XYZ` 顺序分别绕各轴旋转 `30° / 45° / 60°`，最终旋转可表示为多个旋转矩阵的乘积。

若有向量 `v`，旋转后的向量可以直接由：

- `R * v`

得到。

## 2.4 位置 + 姿态 = 空间位姿（Pose）

在机器人学中，一个物体在空间中的完整状态由：

- 位置
- 姿态

共同组成，这就叫做：

- `位姿（Pose）`

通常用一个 `4 x 4` 的齐次变换矩阵来描述。

其中：

- 左上角 `3 x 3` 是旋转矩阵 `R`
- 右上角 `3 x 1` 是位置向量 `t`

因此：

- `R` 描述朝向
- `t` 描述位置

RoboDK 中复制出来的一整块位姿数据，本质上就是这个概念。

### 平移部分的作用

当齐次变换矩阵作用在一个点上时：

- 旋转部分负责改变方向
- 平移部分负责把点整体搬到新的位置

所以 `t` 本质上表示：

- 新坐标系原点相对于旧坐标系原点的偏移

### 一个直观例子

如果旋转矩阵是单位矩阵，而平移向量非零，那么变换的效果就只有：

- 平移

如果既有旋转又有平移，那么效果就是：

- 先旋转
- 再平移

这就是位姿变换的基础。

---

## 2.4.1 齐次变换矩阵的必要性及应用举例

齐次变换矩阵的核心意义在于：

- 将旋转和平移统一到同一个矩阵中
- 用矩阵乘法统一组合多个变换

这样可以大幅简化机器人、视觉和图形中的坐标转换过程。

### 2.4.1.1 机器人运动学

每个机器人关节都有自己的局部坐标系。

使用齐次变换矩阵后，就可以将：

- 基坐标系
- 连杆坐标系
- 关节坐标系
- 工具坐标系

之间的关系统一写成矩阵连乘。

最终就能得到：

- 末端执行器相对于基坐标系的完整位姿

### 2.4.1.2 计算机图形学

在图形学中，一个模型通常要经历：

- 缩放
- 旋转
- 平移

这些都可以统一表示为矩阵，并最终组合成一个总变换矩阵。

优点是：

- 便于硬件加速
- 便于流水线处理

### 2.4.1.3 计算机视觉与 SLAM

在视觉与 SLAM 中，经常需要表示：

- 相机在世界坐标系中的位姿

齐次矩阵能够高效表示：

- 世界坐标到相机坐标
- 相机坐标到机器人坐标

等各种转换关系。

### 2.4.1.4 多设备坐标对接

在多机器人、多相机、多传感器协同中，不同设备有自己的坐标系。

齐次变换矩阵可以统一描述这些设备之间的关系，便于：

- 系统集成
- 坐标对齐
- 控制联动

## 2.5 概念总结

| 概念 | 描述内容 | 常见表达形式 |
|---|---|---|
| 位置 Position | 空间中“在哪里” | 三维向量 `(x, y, z)` |
| 姿态 Orientation | 空间中“朝哪边” | 欧拉角、旋转矩阵、四元数 |
| 位姿 Pose | 位置 + 姿态 | 齐次变换矩阵 `4x4` |

## 2.6 SE3 代码示例

更多示例可参考单独的 `SE3` 示例文档。

下面给出一个基础例子：

```python
# 定义平移：沿 X 平移 1，沿 Y 平移 2，沿 Z 平移 3
translation = SE3.Tx(1) * SE3.Ty(2) * SE3.Tz(3)

# 定义旋转
rotation = SE3.Rz(60, unit='deg') * SE3.Ry(45, unit='deg') * SE3.Rx(30, unit='deg')  # xyz

# 综合平移和旋转
pose = translation * rotation

# 定义一个三维点，假设为 (1, 1, 1)
point = [1, 1, 1]

# 用 pose 对该点做变换
transformed_point = pose * point

print(pose)
print("原始点：", point)
print("变换后的点：", transformed_point)
```

### 注意旋转顺序从右往左计算

#### XYZ

```python
SE3.Rz(60, unit='deg') * SE3.Ry(45, unit='deg') * SE3.Rx(30, unit='deg')
```

#### ZYX

```python
SE3.Rx(gamma, unit='deg') * SE3.Ry(beta, unit='deg') * SE3.Rz(alpha, unit='deg')
```

所以在写代码时，一定要明确：

- 注释中的顺序
- 数学上的乘法顺序
- API 接口实际接受的顺序

## 2.7 Episode 获取姿态

在实际操作中，可通过以下方式验证姿态：

1. 使用 RoboDK 获取当前姿态
2. 使用 API 运动到对应位置
3. 再使用 API 获取当前姿态
4. 与 RoboDK 显示结果进行对比

这样可以帮助确认：

- 坐标系定义是否一致
- 欧拉角顺序是否一致
- TCP 设置是否一致
- API 与仿真软件是否匹配
